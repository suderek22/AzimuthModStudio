Car Pack Studio 0.2.2-beta

Experimental release - How to

Car Pack Studio builds multi-car packs for Forza Horizon 2 on Azimuth and provides a dark desktop workspace for inspecting assets, editing car data and testing vehicles in the embedded game. This is an experimental tool. Back up your game overrides, projects and saves before use. Use a private sandbox runtime and test on copies of your files.

1. Extract and set up

  1. Extract the entire release ZIP into a writable folder. Keep the _internal folder beside the executable; it holds runtime, save_template, resources, bin and application libraries. Do not run directly inside the ZIP.
  2. Run Car Pack Studio.exe. Python does not need to be installed.
  3. Choose your owned game's Mount folder: the folder containing media\stripped\gamedbRC.slt. Base game content is not included.
  4. In File > Settings, leave Runtime set to sandbox for isolated testing. Install Azimuth, FH2 Mod Platform and Extra Options separately into one Azimuth folder first (tested baseline: 1.0.2, 2.8.0, 0.3.2). Set Copy dependencies from to that folder, or use Mods > Import dependencies. The bundled save template supplies the generated test save. Missing required files block wrapper launch, not editing or building packs.
  5. Select existing only when intentionally using another Azimuth installation, then choose its folder. Back up that installation first: mods/settings and pack files are installed into that runtime.

Sandbox settings include initial spawn location, title-screen assistance, crash recovery and telemetry HTTP port. The test save is always regenerated from the shipped template on preparation, even with older settings that disabled it; do not use the sandbox for a career save you want to keep. The garage uses a curated maximum of 250 entries; custom test cars and the selected start car are included as needed. Credits default to 999,999,999.

2. Workspace

Right-click a dock title and click a panel name to show or hide that panel. Pack and Car properties are hidden by default; turn them on from this menu for pack editing.

  • Cars: the mounted base/asset-overlay car catalogue. Columns are ID, Car, Media and Source. Click a header to sort, or search by ID/name/media/source. Right-click a car to open it in Explorer, clone it into the pack or test it. With the wrapper running, Spawn creates a driverless car and Spawn Drivatar creates generic AI, initially paused. The shared limit is four cars; wait for each car to activate before spawning another. This catalogue is based on the base database; custom project cars are managed in the Pack panel.
  • Explorer: files belonging to the open vehicle. Filter by path/name, double-click to open a tab, or right-click to open, export original bytes, replace from a file, or revert a project override. Modified entries are highlighted.
  • Pack: cars in the current project, plus Import car ZIP, Build, Install and Test in game. Select a row to edit its properties; double-click to inspect that car's files.
  • Car properties: in-game name, short name, year, existing/new brand, car ID, thumbnail reference and additional Data_Car column overrides. Media name and donor are displayed. Click Apply to save changes into the project.
  • Middle tabs: the Wrapper and opened editors/viewers. Close a document with its tab close button. Unsaved text edits prompt before closing.
  • Output: project/build/install diagnostics. Dock panels can be moved or floated.

Runtime tabs beside Explorer and Cars

  • Maps: keyed by world ID (Anthem 542, TheIsland 549). Right-click for Change map or Teleport, including your custom points marked [custom]. If necessary, travel completes first; the teleport is sent only after confirmed settled arrival. Failed/timed-out travel cancels the follow-up. Stop cancels it too. Storm Island must be mounted. Custom-map bookmark IDs are retained, but native travel currently supports only 542 and 549. Placeholder and race-route database rows are not additional playable maps.
  • Events: supported standard races grouped by map, keyed by AnthemEventRaceId. Right-click to start a specific event (automatically travelling to its map first). Use Event stop or the event stop console command to return to free roam once the race is running; wait for its intro/countdown to finish first. These are real events with normal save/progression rules.
  • Spawned: automatically tracks Studio-owned native objects, including console changes. Object IDs differ from car IDs. Right-click to delete, swap to an active driverless car, return to your original car, or pause/play/reset an AI car. Clear all removes only Studio spawns. Follow/chase remain unavailable. Stale native snapshots are labelled and row actions disabled. Busy command pipes use bounded native waits; an outage is logged once, with a recovery notice when polling resumes. Sent commands are never replayed automatically after a reply timeout. Clear spawns before map travel, teleport, events or player-car reload; the GUI never silently deletes them for you.
  • Mods: installed runtime mods, platform, Extra Options and packs with their reported versions. Offline versions are marked last-session; missing version metadata is marked unknown. Right-click to open the installed INI directly in an editor tab. Save normally; most changes apply on restart.

Wrapper preparation still manages the Studio-generated INI, telemetry port and FPS toggle. Change those values through wrapper/settings controls; preparation reapplies them on the next run.

Mods > Open Studio Mods opens the selected runtime's fh2-mods folder. Import dependencies copies known required files and Azimuth data\bin support files from an installed Azimuth folder. Installed optional ShowFPS, FH2 Mouse & Keyboard and NoPause (qiangqiang101) are also copied. Saves, caches, logs, game files and unknown mods are not imported. The first import copies launcher/DLC paths; later imports preserve destination INI/DAT settings. Close games using either folder before import. Required dependency file detection does not certify versions. Azimuth, the mod platform and Extra Options are installed at the runtime root/data\bin, not in fh2-mods.

The camera icon at the wrapper toolbar's upper right saves the native game client to %APPDATA%\CarPackStudio\screenshots as a uniquely named PNG, at the client window's actual physical-pixel resolution (no scaling or editor chrome), embedded or detached. It does not upscale the embedded client to a different internal render resolution. The game must not be minimized; failed or black capture surfaces report an error. The Studio telemetry overlay is off by default and is not included in client screenshots.

The application's version is always shown in the bottom-right status bar. In File > Settings, Check updates now checks GitHub's latest published release. Optional automatic startup checking is off by default. A newer release shows a popup linking to AzimuthModStudio on GitHub. No update is automatically downloaded or installed. Network errors are reported in Output/status.

3. Create and edit a pack

  1. Use File > New pack project (Ctrl+N), choose a name and a project folder. Use Open project (Ctrl+O) to reopen a .cpsproj file; Save project saves its metadata.
  2. In Cars, right-click a donor and choose Add to pack as new car (clone). The donor supplies the database/physics configuration and asset source.
  3. Alternatively, use Pack > Import car ZIP. Choose an asset archive containing a root .carbin and .modelbin files, then select a database/physics donor. The ZIP is copied into the project's sources folder, and its assets replace the donor's asset source.
  4. Choose a unique numeric car ID and a unique media name. Renaming binary asset references requires the media name to have the same character count as the asset-source archive name. Names use letters, numbers, underscore or hyphen.
  5. Edit properties, click Apply, open files in Explorer, and save text edits or replace assets. Repeat to add multiple cars to the same pack.

Project metadata is stored in .cpsproj. Per-car overrides live under cars\<media>; imported ZIP sources live under sources. Keep these folders with the project.

Remove versus uninstall

Right-click a particular car in the Pack panel:

  • Remove car from pack: removes it from the project after confirmation. Its asset tabs close, discarding unsaved edits as stated in the confirmation. Source/override files stay on disk. An already-installed copy is unchanged.
  • Uninstall car from game database: removes only that custom car from an installed CPS pack, its manifest entry and generated override database rows. Stop the wrapper and close other game instances first. Other cars and the base database are preserved. The car stays in the project; installing/testing the project again installs it again. Changes apply on the next launch. Base-game database cars cannot be uninstalled with this action.

Pack > Uninstall a pack removes a whole installed pack instead.

4. Build, install and distribute a car pack

  1. Click Build to generate the project's build folder with asset ZIPs, database SQL, strings and pack metadata. Review Output for errors.
  2. Click Install to build and install into the selected runtime's CarPacks folder and the game's Mount\mediapc overrides. The original base database is not edited.
  3. Pack > Show generated SQL opens the SQL/string changes for inspection.
  4. Pack > Export distributable zip writes the pack's build output and installation README. The destination requires FH2 Mod Platform 2.8.0, Extra Options with media overrides enabled, and CarPackLoader.dll supplied with this tool's runtime. Follow the generated manifest instructions.

Pack installation persists on disk. Testing before a manual install still builds/installs the pack: it is not a session-only in-memory database. Rebuild and restart after asset/database changes.

5. Editors and file viewers

  • Text: XML/XAML, AVPINS, TXT, LOG, INI, SQL and JSON. Use Find (Enter for next result), Ctrl+F to focus Find, Save/Ctrl+S to save, and XML Format/validation for XML documents. Car edits become project overrides. Loose-file edits save directly to the chosen disk file; archive entries opened through Game files manager are read-only.
  • Swatchbin: view the decoded texture on a checkerboard, toggle RGBA channels, Fit, wheel-zoom and drag-pan. Double-click to fit. Export PNG writes the original decoded RGBA image, independent of channel-preview toggles.
  • Modelbin: left mouse orbits, right/middle mouse pans, wheel zooms. Toggle individual meshes, Show all/Hide all, Wireframe and Unlit normals.
  • Binary inspection: materialbin/shaderbin bundle structure and metadata; PSO/VSO DXBC chunks; FH2 carbin scene header and asset references; lights.bin attachments and transforms. Physics definitions, binary light presets and other binary files have read-only header/string/byte inspection. Bytes are paged in 64-KiB blocks; strings/references include byte offsets.
  • Audio banks: select a sample, Play/Stop, or Export WAV. Double-click a sample to play. PCM16, mono/stereo XMA and MPEG sample decoding are included. Event-only banks contain no audio samples; unsupported codecs report an error. Conversion happens through a bounded background decoder process.

6. Tools menu

Game files manager opens a reusable tab rooted at Mount. Browse supported loose files on the left, select a ZIP to list supported entries on the right, and filter archive entries by name. Double-click a file/entry to open it in the appropriate viewer. Choose folder changes the browser root. Open file from disk uses the same readers; choosing a ZIP opens its archive listing. Open game logs opens the current platform.log snapshot. Console detach/attach moves the same console between the Wrapper and a separate resizable window. The small square Detach/Attach icon beside the console input does the same, preserving its draft, history and output (equivalent to console 1/console 0).

7. Test in the Wrapper

  1. Select the intended car and use Test in game (F5) or Run. The selected sandbox runtime, mods and test save are prepared before launch.
  2. The game starts inside the Wrapper with launcher bypass and title-screen assistance. Use an XInput controller for game input, or install optional FH2 Mouse & Keyboard. Initial embedding waits for the input mods to discover the top-level game window, then sets native focus on the embedded child. A 20-second readiness timeout reports a warning instead of hanging startup. If an external input mod still cannot initialize, use game-window Detach/Attach and inspect platform.log.
  3. The toolbar provides Run, Stop, game-window Detach/Attach, Skip title screen, Telemetry overlay and ShowFPS. ShowFPS is greyed out when its DLL is absent. Its saved setting applies on the next run; F11 toggles its overlay in game. The running-car label follows telemetry.
  4. The game-window Detach/Attach control is a square icon with a tooltip. Wrapper > Settings > Travel test binds reserves physical radio controls for the experimental flow. Uncheck it while stopped and then Run to change radio stations normally. Console/GUI car reload, teleport and map travel remain available with either setting. This startup setting cannot change during a run.
  5. Use Wrapper > Time & Weather (Ctrl+W) for sliders, freeze and weather presets. Use Wrapper > Car > Animations to list/play the active car's animation states.
  6. Wrapper > Teleport > List lists built-in places followed by custom ones. It uses the same confirmed map-change-then-teleport sequence as Maps. My places opens the bookmark manager with map ID, map name, name and X/Y/Z columns. Enter a name and choose Add current position to capture the settled car's coordinates; select a row to teleport there or delete that exact map-qualified bookmark.
  7. Wrapper > Volume sets saved wrapper-process audio volume from 0 to 1, including decimals. It applies when the game's audio session appears, without changing system master or other processes.
  8. Testing another car while already running sends its car ID to live reload instead of restarting. New/changed assets or database rows require Stop then Run.
  9. Stop or Shift+F5 stops the owned game process. Closing Car Pack Studio also stops its wrapper.

Live swaps use the native fast-travel loading/arrival flow in free roam and preserve the position. Radio-left is reserved for that reload flow in these test sessions. Progress is logged, and a 60-second timeout offers Recover previous car. Recovery is explicit and restarts at the normal spawn point, not the exact old coordinates. Do not treat crash recovery as protection against every possible engine fault.

8. Console commands

Press Enter to submit. Up/Down recalls commands for this application session and restores a draft when you return past the newest entry. Tab completes at the end of the input line, first extending the shared prefix and then cycling matches; Shift+Tab cycles backwards. Suggestions include subcommands, map destinations, quoted custom bookmarks and session history. Completion never sends a command; press Enter when ready. Most Studio shortcuts are automatically prefixed with CarPackStudio. Platform commands use <mod name> <command>; list displays available commands.

Filter matching is case-insensitive, OR between includes of the same field, AND between text/resource fields. Exclusions win. The Filters button manages the same rules and turns green when any are active. Filter changes reapply to retained output; command feedback stays visible. Scroll upward to pause following; Latest returns to new entries. Focus and new messages do not reset a paused scroll position. Repeated car-status polling trace lines are hidden. Azimuth diagnostics observe pipeline API calls, not every internal function or thread operation. A fully cached scene can be quiet until another pipeline is created/loaded. Other mods expose only the details they log. Console filters still apply. The detached console opens at 1000 x 700, minimum 640 x 400; closing it reattaches without losing state.

XInput scripts: record while playing, press Stop, then save JSON or Play. Buttons use standard XInput bit masks; triggers are 0-1 and sticks are -1 to 1. Playback replaces the selected game's controller readings, then supplies neutral input for 250 ms before returning control to the physical controller. Keep a controller connected and the game focused. Scripts retain wall-clock timing, including loading screens; there is no automatic wait for gameplay. Recordings are limited to 30 minutes / 100,000 state changes. The native transport is fh2-mods\CPSInput.bin; JSON is portable between sessions.

Teleport: the tool reads exit locators from the mounted game's Route0.nt, rather than relying on placeholder entity positions. Airport uses its fixed coordinates instead of a named exit locator. Storm Island uses verified authored exit/fast-travel coordinates. Unknown destinations and coordinates for a map other than the loaded map are rejected without starting a reload. Requests wait for settled free roam. The normal 60-second reload recovery applies when the current car can be resolved. Recovery restarts at the normal spawn; it does not restore an exact position. Use track TheIsland / track Anthem for map changes; tp does not change maps. Custom places persist independently of Settings in %APPDATA%\CarPackStudio\teleport_places.json. They retain numeric track IDs, including custom tracks already loaded by the game. This does not enable arbitrary-ID map switching. Save errors and invalid bookmark files are reported without silently resetting the file. For cross-map investigation, start a transition capture, travel through a track command or the game's own map-change UI, then Stop and export. Captures contain up to 100,000 transitions.

Model viewer LOD filter: use the LOD selector beside Wireframe to show a mesh-name suffix such as engineBay_a_LOD0, engineBay_a_LOD1 or engineBay_a_LODS. Legacy LOD prefixes are also supported. Parts without a LOD tag remain available. Mesh checkboxes are retained when switching filters; Show all / Hide all update those choices without overriding the selected LOD filter.

9. Logs and safe operation

Use Output for build/preflight checks and the wrapper console for live logs. The runtime keeps platform.log, Extra Options/Azimuth logs and CarPackStudio-critical.log; crash records are under fh2-mods\crashes. The project receives diagnostics.log after wrapper preflight. If a car fails to appear, check its ID, archive paths and the CHECK messages before rebuilding. Stop the wrapper before installing/uninstalling. Uninstall changes the selected runtime only; another installation has its own CarPacks folder.

Technical details

  • Release: 0.2.2-beta, Windows x64, PySide6/Qt desktop GUI packaged with PyInstaller. OpenGL compatibility rendering is used by the model viewer. Python is bundled.
  • The workspace always uses the dark theme, including floating panels. Drag an individual panel tab outside its strip to dock at the left, right, top or bottom edge; an outline previews the drop. Drop outside Studio to float that panel. CarPackStudio.dll file, product and mod versions are 0.2.2.
  • Only CarPackLoader, CarPackStudio test mod and Virtual Dashboard are bundled runtime mods. Azimuth, FH2 Mod Platform, Extra Options, ShowFPS, mouse/keyboard and NoPause are not redistributed. Install them separately. Without NoPause the game may pause when losing focus.
  • Sandbox location: %LOCALAPPDATA%\CarPackStudio\runtime. Settings: %APPDATA%\CarPackStudio\settings.json. Telemetry: Virtual Dashboard HTTP API, port 8080 by default. Default game launch arguments: --game=fh2 --skip-launcher. Edit Azimuth launch arguments in File > Settings, alongside the Game Mount folder. Enter arguments only, without azimuth.exe; double-quote paths containing spaces. An empty field launches with no arguments. Reset to default restores the defaults. Changes apply on the next wrapper launch and do not restart a running game.
  • Pack data: fh2-mods\CarPacks\<pack>\pack.sql, strings.txt and pack.json. Assets/manifest: Mount\mediapc. Generated database overrides can be in mediapc or mediaoverride. The base Mount\media\stripped\gamedbRC.slt is read-only to the pack builder/uninstaller.
  • Per-car uninstall splits generated SQL by car, preserves other sections and shared strings, backs up installed pack.sql/pack.json as .bak, and deletes that custom ID's generated car/upgrade rows. Retained asset ZIPs and project files allow later rebuilding; they are not recursively deleted.
  • Binary assets use little-endian readers. burG bundle metadata, DXBC containers and verified FH2 car/light fields are shown without writing back binary changes. Texture detiling uses xg.dll; audio conversion uses the bundled FFmpeg executable.
  • Save generation uses the bundled template and the supplied base database, creates a sandbox save revision, and inserts selected custom test cars. Base game archives are required and are not part of this release.
  • Application icon: original garage-and-spanner vector artwork created for this tool, with editable resources/app-icon.svg and generated PNG/multi-resolution ICO. No exported game pixels are used.
